## Hypotheses and suspicions

- Login form may accept whitespace-padded or case-variant usernames; boundary behavior is unverified.
- Cart badge count may desync after rapid add/remove or navigation without full page reload.
- Inventory sort or filter controls (if present) may interact unexpectedly with cart state.
- Error messaging for bad credentials may be inconsistent with product tone (HICCUPS: Image, Product).
- Public demo inventory labels or product count may drift from inferred requirements (RSK-001).

## Heuristic plan

### Session time split (new-feature context)

| Phase               | Duration | Activity                                                                        |
| ------------------- | -------- | ------------------------------------------------------------------------------- |
| Orient              | 15 min   | Survey login page, inventory layout, cart entry points; note selectors and copy |
| Explore             | 40 min   | Execute JRN-001 and JRN-002; apply HICCUPS on each screen transition            |
| Boundaries / errors | 20 min   | Invalid login (REQ-003), back-button after add-to-cart, empty cart edge         |
| Document            | 15 min   | Tag observations; draft debrief and follow-up charters                          |

### Heuristic lenses (priority order)

1. **Claims (C)** — Does observed behavior match REQ-001/002/003 and journey outcomes?
2. **User expectations (U)** — Is login → inventory → cart intuitive for a first-time shopper?
3. **State transitions** — Skip steps, use browser back, refresh mid-flow, repeat add-to-cart.
4. **Error handling** — Wrong password, empty fields, locked account if credential available.
5. **World (W)** — Responsive layout at narrow viewport; public network latency tolerance.
