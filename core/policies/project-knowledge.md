# Project Knowledge Contract

The project context is the first read and contains exactly these required concerns:

1. Product
2. Tech Stack
3. Test Stack
4. CI/CD
5. Environments
6. Quality Goals
7. Risk Areas
8. Team
9. Conventions

Completed project contexts contain no bracketed placeholders. Facts include inline status, source, and date where authority matters.

Qali authors and maintains these governed sources by default; humans may edit them or supply authority. Use one owner per concern: context for setup and conventions; reference for product facts; journeys for end-to-end experience; risk matrix for scored risks; strategy for durable approach; plan for current scope; scenarios for test intent; test data for accounts and fixtures; questions for unknowns; and decisions for recorded authority.
