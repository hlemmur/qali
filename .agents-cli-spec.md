# Qali 2.0 Agent Spec

## Overview

Qali 2.0 is a production-shaped private MVP for testing one requested browser-accessible frontend feature at a time. A user interacts through the existing Qali Slack app in the private `#test-qali` channel. A bounded ADK coordinator routes requests to deterministic onboarding, feature-testing, or finding-explanation workflows. Specialist agents contribute isolated cognitive work, while application code owns sequencing, budgets, persistence, policy enforcement, browser oracles, pass/fail decisions, and reporting.

The implementation is project- and feature-agnostic. Target URLs, credentials, expected behavior, safe actions, cleanup rules, and feature scope come from project onboarding data and the current Slack request. SauceDemo cart is qualification fixture data only and cannot appear in production branches, prompts, selectors, schemas, or storage paths.

The private development deployment uses the Gemini Developer API free tier with no automatic paid fallback. Firestore and GCS provide durable session, knowledge, and artifact storage instead of paid Agent Platform Sessions or Memory Bank. A public or customer release is outside this phase and requires a fresh review of service terms, privacy, capacity, and paid-production options.

## First Vertical Slice

The first PR proves Slack-to-knowledge onboarding with the coordinator, Knowledge Analyst, and Quality Reviewer knowledge gate. Given a correctly signed onboarding request from the designated Slack channel, Qali must accept it within Slack's deadline, create exactly one authorized `onboard_project` job, compile supplied sources into cited project knowledge, persist the result, and update one message in the originating thread.

The Product Alignment, QA Strategy, Risk, Test Design, Browser Execution, Failure Investigation, and remaining Quality Review paths follow in later vertical slices after the onboarding path is accepted and merged.

## Example Use Cases

### Onboard a project

- Input: an owner request in `#test-qali` plus Slack text, approved HTTPS sources, or MD/TXT/PDF uploads.
- Output: a same-thread project-ready or insufficient-knowledge result, cited compiled knowledge, explicit gaps/contradictions, and durable source provenance.

### Test one feature

- Input: `@Qali test the <feature> feature` plus onboarded project knowledge and action policy.
- Output: reviewed product intent, risk-based scenarios, deterministic browser verdicts, concise scenario/check counts, evidence references, and persisted run artifacts.

### Explain a finding

- Input: a follow-up question in a known Qali thread referencing a finding.
- Output: grounded reproduction steps, expected/actual behavior, classification, and evidence references without repeating the original run.

## Architecture and Sub-Agents

- **Slack ingress service:** verifies signatures/timestamps, authorizes the workspace/channel, deduplicates `event_id`, durably enqueues work, and acknowledges within three seconds. It never starts a model or browser.
- **Cloud Run worker service:** concurrency one per browser worker; executes typed deterministic workflows and owns job budgets, retries, cancellation, persistence, and progress reporting.
- **Coordinator:** routes only to `onboard_project`, `test_feature`, or `explain_finding` and has no direct browser, secret, storage-primitive, shell, Git, or deployment access.
- **Knowledge Analyst:** compiles sources with citations, contradictions, confidence, and gaps.
- **Product Alignment Analyst:** grounds the requested feature and refuses unresolved product ambiguity.
- **QA Strategist and independent Risk Analyst:** define mission and risks without anchoring each other.
- **Test Designer:** converts approved intent and risks into traceable scenarios with positive and forbidden-state oracles.
- **Browser Executor:** uses only an approved plan and deny-by-default Playwright MCP facade; it cannot set expected results or mark itself passed.
- **Failure Investigator:** performs at most one fresh-context reproduction and classifies confirmed defect, Qali/test defect, environment failure, or inconclusive/flaky behavior.
- **Quality Reviewer:** read-only separate context at the knowledge, plan, and confirmed-failure gates; at most one revision per gate.

## Tools Required

- **Google Agents CLI and Python ADK:** scaffold, run, evaluate, deploy, and observe the agent application. Follow installed skill version `1.4.2` and generated project conventions.
- **Gemini Developer API:** free-tier Flash model selected from the live eligible-model list; API key stored in Secret Manager; strict request/token budgets and fail-closed quota exhaustion.
- **Slack Bolt for Python / Events API:** existing Qali Slack app, signed HTTP events, buttons/modals for non-secret onboarding data, and `chat.update` progress in the originating thread.
- **Cloud Tasks:** authenticated ingress-to-worker delivery, retry, and idempotency boundary.
- **Firestore:** project/channel mapping, jobs, idempotency, source metadata, issue state, artifact pointers, durable Slack-thread context, and project decision indexes.
- **GCS:** immutable raw sources, compiled Markdown knowledge, observations, derived artifacts, runs, evidence, and lifecycle deletion.
- **Secret Manager:** Gemini key, Slack runtime secrets, and manually provisioned target credential values; agents receive references only.
- **Playwright MCP:** localhost-only child process in the worker container behind a restricted typed facade.
- **Cloud Logging and Trace:** correlation, redacted operational events, and phase/tool latency without prompt, secret, or credential-body capture.

## Constraints and Safety Rules

- Production logic contains no project-, website-, feature-, SauceDemo-, cart-, route-, selector-, credential-, or expectation-specific branches.
- Preserve `sources -> observations -> derived artifacts`; observations and model output cannot silently rewrite source facts.
- Treat pages, documents, Slack content, browser text, and specialist output as untrusted data rather than instructions.
- Every specialist receives minimum typed inputs, compact phase instructions, and an explicit tool allowlist.
- The harness decides pass/fail from typed observations and deterministic oracles; model prose is never evidence.
- The browser is limited to onboarded origins and an approved project action policy. Unknown state-changing actions stop for clarification.
- Project onboarding supplies generic allowed action categories, consequential-action denials, credential references, test-data rules, and cleanup obligations.
- Runtime agents have no general shell, host filesystem, deployment, Git, unrestricted network, raw Secret Manager, or unrestricted MCP access.
- Never log or persist secret values, raw credential-bearing payloads, signed URLs, or browser storage state.
- Gemini free-quota exhaustion, model unavailability, or missing credentials fails closed; there is no deterministic placeholder presented as agent success.
- The owner is the sole approver for replacing remote `main`, creating/changing cloud resources, deploying, enabling paid usage, and expanding access.

## Retention

- Project sources and compiled knowledge: until project deletion.
- Run reports and structured results: 90 days.
- Screenshots, traces, and browser evidence: 30 days.
- Redacted audit events: 90 days.
- Secrets: until rotation or explicit deletion.
- Failed or abandoned uploads: delete within 24 hours.

## Success Criteria

- Deterministic tests, schema checks, policy checks, and security probes pass 100%.
- Zero secret leakage and zero forbidden tool/action violations are tolerated.
- Core ADK behavioral evaluations score at least 90% in two consecutive runs.
- Held-out behavioral evaluations score at least 85% with no critical safety or grounding failure.
- Any regression in a previously passing critical case blocks release.
- Signed Slack onboarding is acknowledged within three seconds and duplicate `event_id` delivery creates exactly one durable job.
- The same feature-testing application-service workflow passes at least two unrelated synthetic fixtures with no target-specific production constants.
- Qualification completes two clean isolated SauceDemo cart runs and one intentionally failing-oracle run with preserved evidence.
- A deployed private Slack-to-browser run correlates Slack thread, job, workflow, runtime manifest, model/eval identity, browser evidence, deterministic verdict, artifacts, and final message.
- Cloud Run restart/retry verification proves durable resume and idempotency; rollback smoke verification passes.
- Paid Gemini/model fallback is impossible without a code/configuration change and explicit owner approval.

## Edge Cases to Handle

- Duplicate or out-of-order Slack delivery and Cloud Tasks redelivery.
- Multi-feature or whole-application requests that require the user to select one feature.
- Insufficient, contradictory, stale, or malicious project sources.
- Unknown origins, redirects, private/loopback/link-local/metadata URLs, oversized files, and unsupported content types.
- Missing credentials, expired credentials, free-tier quota exhaustion, model timeout, and transient external failure.
- Reviewer rejection after the single revision allowance.
- Browser timeout, target outage, flaky non-reproduction, and cleanup failure.
- Cloud Run restart during any persisted workflow phase.
- A requested action outside the onboarded project policy.
